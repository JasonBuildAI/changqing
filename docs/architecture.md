# 架构

> English summary: changqing keeps four layers of memory (L0 raw utterances, L1 facts
> on an append-only operation log, L2 summaries, L3 persona weights), writes L0 on the
> conversation path and consolidates into L1 on a background thread, and resolves every
> external capability through an injected protocol instead of importing a host module.

这一页回答「东西住在哪儿、谁能碰谁」。**为什么不是「讲设计」**：设计是取舍的理由
（见 [设计](design.md)），架构是边界 —— 它该能回答「这段代码允不允许写这个文件」。

## 一页总览

```
                         ┌──────────── 宿主 ────────────┐
                         │  身份、会话、prompt、账单      │
                         └──────┬───────────────┬───────┘
        Embedder / LLM / UsageSink（注入）        │ Memory(uid, config=…)
                                │               │
   ┌────────────────────────────▼───────────────▼─────────────────────────┐
   │                             changqing                                │
   │                                                                      │
   │  写入这条路（对话热路径，一次磁盘追加）                                │
   │     remember() ──► store.turnlog ──► sessions/YYYY-MM-DD.md          │
   │                                                                      │
   │  整理这条路（后台线程，每轮 0 次模型调用）                              │
   │     worker ──► extract（七道闸）──► store.ops(log.jsonl) ──► index     │
   │                  │                                       ▲           │
   │                  └──► summaries / topics                  │           │
   │                                        consolidate ───────┘           │
   │                                        vectors（可选）                 │
   │                                                                      │
   │  读取这条路（对话热路径，只读）                                        │
   │     context() ──► retrieve：热路径 + 冷路径 ──► 预算裁剪 ──► 卡片       │
   └──────────────────────────────────────────────────────────────────────┘
```

## 四层，各自的职责边界

| 层 | 谁写 | 谁读 | **不许做什么** |
|---|---|---|---|
| L0 原话 `sessions/` | `store.turnlog.remember` | 抽取、导出 | 不许改、不许合并、不许覆盖已有字节 |
| L1 事实 `log.jsonl` + `index.sqlite` | 只有 `store.ops.append_op` | 检索、卡片、导出 | 日志只追加；索引是它的投影，**不许**成为任何结论的唯一来源 |
| L2 纪要 `summaries` | 抽取那一趟顺手写 | 注入（故事线） | 不许当事实用：它是散文，允许裁剪、允许含糊 |
| L3 画像 `persona_attention` | 抽取时按注入的画像打分 | 重排、渲染 | 不许写死在库里：形状固定，内容由 `PersonaProfile` 给 |

一句话概括这套边界的价值：**只有 L0 与操作日志不可再生**。别的都可以删了重建，
所以「备份」只需要备份这两样（细节见 [存储](storage.md)）。

## 一轮对话的两条路

**写（他刚说完一句话）**

1. 宿主调 `mem.remember({"user": …, "assistant": …})`；
2. `store.turnlog` 追加一行到当天的 `sessions/YYYY-MM-DD.md`，更新 `state.json`
   里的轮次计数与序号；
3. `worker.notify(uid)` 只是**放一个 uid 进队列**（不阻塞，不同步抽）。

这一步必须便宜：它压在首字延迟上。所以这里**没有任何模型调用**，也没有索引写入。

**读（这一轮该把什么摆到她面前）**

1. 宿主调 `mem.context(query, recent_refs=[…])`；
2. 热路径：钉住的 + 承诺 + 按权重排在前面的那几条（恒定开销）；
3. 冷路径：只在**他提到过去**或热路径没料时才跑，走槽位 / 全文 / 向量三路召回，
   用 RRF 融合，再按画像重排；
4. 预算裁剪：事实、故事线、话题三份各有各的预算；
5. 返回卡片。**这一步不写 L0，也不改事实** —— 它只把「用过的」记在派生层。

两条路共用一个函数：`context.context_facts()` 是「这一轮有什么素材」的**唯一**判据，
门控与渲染都读它。这条规矩是被一次真实缺陷逼出来的：两边各写一份字段清单，
其中一份漏了一栏，于是「她手里只有一条承诺」时门控说没料、卡片里却写着那条承诺。

## 模块地图

| 模块 | 归它管的一件事 |
|---|---|
| `config.py` | **唯一**读环境变量的地方；产出一个冻结的 `MemoryConfig` |
| `runtime.py` | 进程级装配：配置 + 画像 + 三个注入的能力 |
| `ports.py` | 三个 Protocol 与它们的空实现（`NullEmbedder` / `NullLLM` / `NoUsage`） |
| `persona.py` | 画像的形状（`PersonaProfile`）与中性默认值 |
| `types.py` | 核心数据形状的 `TypedDict`（`Fact` / `Turn` / `MemoryContext` …），与实现**逐键对齐**，由 `tests/test_types.py` 机械校验 |
| `store/` | 落盘：L0、操作日志、物化索引、纪要、话题、渲染视图 |
| `extract.py` | 抽取：prompt、解析、回引校验、时间绝对化、冲突消解 |
| `retrieve.py` | 检索：热 / 冷路径、RRF、画像重排、预算裁剪、卡片文本 |
| `context.py` | 工作面：这一轮有什么素材（门控与渲染的唯一判据） |
| `consolidate.py` | 巩固：去重合并、衰减、打扫索引 |
| `worker.py` | 后台线程：三个触发条件、游标、幂等与调用上限 |
| `vectors.py` | 向量索引的写入侧（可选层，没注入 `Embedder` 时整支不进） |
| `edit.py` | 手改一条事实的白名单与校验（`EDITABLE_FIELDS`） |
| `memory.py` | 门面 `Memory`：把上面这些拼成一个对象的用法 |
| `server/` | 可挂载的 FastAPI 路由（相对路径，前缀归宿主） |
| `adapters/` | 现成实现：离线替身、OpenAI 兼容端点 |

### 四条机械护栏

上面那些「不许」里有四条是能被机器检查的，所以它们不靠自觉：

| 护栏 | 检查什么 | 它防的是哪种「靠人看不出来」 |
|---|---|---|
| `tests/test_no_host_coupling.py` | 有没有 import 宿主那个顶层包 | 在宿主里跑得好好的，换一个进程就 `ImportError`；藏在函数体里的那种连 import 时都不报错 |
| `tests/test_no_private_terms.py` | 有没有混进属于宿主、本机、或那个具体角色的词 | 这些词是**顺手带过来**的：一句真实对话样例、一个绝对路径、一个角色名，review 时看着都无害，然后跟着仓库一起公开 |
| `tests/test_config_injection.py` | `config.py` 之外有没有第二处读环境变量 | 那份值在导入时被固化，之后测试里换掉的配置**改不到它、而且不报错** |
| `tests/test_line_endings.py` | 有没有哪个文件带着 `\r` | 落单的 `\r` 会让 git 把整份文件判成二进制、跳过 CRLF→LF 归一化，下一次 diff 长成「整份文件重写」，而它**一个字都不报错** |

四条都各自先证明自己**认得违规样本**，再去扫仓库 —— 一条从不失败的护栏比
没有护栏更糟：它让人以为这件事有人在管。行尾那条还多做一步：**真的往仓库里
放一份违规样本、确认扫描器点名了它、再删掉**。因为「认出 `\r` 是 `\r`」
证明不了扫描器还覆盖着这棵树，而它最可能坏掉的方式恰恰是后者。

## 依赖方向：两个地方必须反向 import

正常方向是「上层调下层」：`memory → worker → extract → store`。**有两处反向**，
而且它们都是环，只能靠函数体内 import 断开：

| 环 | 断在哪儿 | 挪回模块级会怎样 |
|---|---|---|
| `store.index → store.render → store.facts → store.index` | `render.py` 在函数里 import `facts` | 模块级互相 import 直接 `ImportError`，起不来 |
| `extract → store`、`retrieve → store` | 在函数体内 import | 循环导入，或导入时就把配置与文件系统拉起来 |

这不是风格问题：**环断了之后，`import changqing` 才不需要碰文件系统** —— 它只
装配一份配置，谁来用谁才开库。

## 进程级运行期，以及它的边界

配置有上百处要读（根目录、预算、阈值）。把配置顺着参数一层层传下去要改几百个
调用点；写成模块级常量则撞上另一个坑：**模块级拷贝改不动，而且不报错**
（把根目录指向临时目录，某个模块里那份拷贝还指着真实数据目录 —— 于是测试写进了
生产数据）。

取的是第三条路：一个**显式的、可替换的**进程级对象 `runtime()`，子模块每次用的时候
现取，而不是在导入时把值拷走。测试用 `using()` 换一份，作用域结束自动还原；
`Memory` 句柄则只存**写下来的**覆盖项，每次调用现拼（这样构造之后再 `configure()`
也看得到）。

**边界**：一个进程里只有一份生效的配置。要「同一个进程里两个库各用各的配置」，
得把它改成显式传参 —— 那是接口变更，不是改个默认值。多租户服务请一个 uid 一个
进程，或者接受这一条。

## 线程

- **一个后台线程**（`worker.MemoryWorker`）+ 一个队列。整理是慢活，它与对话那条路
  共享的唯一东西是**每个 uid 的一把锁**：读-改-写状态、追加日志都在锁里。
- 那条几百毫秒的模型调用**在锁外**：拿着锁调模型会让前台写 L0 排在这后面。
  代价是调用回来之后必须重新读一遍状态再写（否则会把这期间前台写的东西盖掉）——
  这个坑在 `worker.extract_uid` 的 `_advance` 里写着。
- 索引是 WAL 模式；`mark_used` 这类「派生层的记账」失败**不往上抛**：它只影响排序，
  不该影响她这一轮说不说话。

## 每一环的失败姿态

这是这套设计里最该被记住的一张表 —— 「挂了」与「降级」是两件事，混起来就是
静默丢记忆：

| 环节 | 失败时 | 为什么不能反过来 |
|---|---|---|
| 写 L0 | 返回空列表，不抛 | 一次磁盘异常不该让整段对话崩掉 |
| 抽取调用 | 抛 → 上游读成「失败」→ **游标不推进**，下次重试 | 吞成空串 = 那几轮原话被当成「已整理」，静默丢数据 |
| 没注入 `LLM` | `LLMNotConfigured` → 上游读成「这条路本来不通」→ 游标照常推进 | 混进上一条会变成无限重试 |
| 向量编码 | 返回 `None` → 这一轮降级到槽位 + 全文 | 抛出去会让整条链路取不到任何记忆 |
| 检索 | 捕获一切，返回空列表 | 「这轮没有可注入的」比「她这一轮说不出话」好 |
| 物化失败 | 索引可重建：删掉重放日志 | 拿索引当唯一事实源就等于把可重建的东西当了真源 |
| 渲染 `facts.md` | 返回 `None`（它只是给人看的视图） | 为一个派生视图让写操作失败 |

**「吞掉」不等于「静默」**：凡是被吞掉的地方都留了一笔（`retrieve.stats()` /
`retrieve.last_error()`）。少了这一句，「热路径因为内部错误一直是空的」在日志里
一个字都没有，表现只是「她记性不太好」。
