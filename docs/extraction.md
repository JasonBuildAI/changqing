# 抽取

> English summary: extraction is a separate model call with its own prompt, and every
> candidate fact has to pass seven gates before it lands in the store — citation
> presence, citation verification against the cited turn, speaker attribution, date
> normalization, cleaning, same-slot conflict resolution, and idempotence.

抽取做的事只有一件：**把一轮原话变成一条带证据的事实**。这一页讲那七道闸各自
拦什么，以及为什么每一道都不能省。为什么抽取必须是一次独立的调用（而不复用
陪聊的 prompt）见 [设计](design.md)。

## prompt 的铁律

prompt 在 `src/changqing/extract.py` 的 `EXTRACT_SYSTEM` 里，十条铁律，其中最
容易写错的三条是：

| 铁律 | 为什么 |
|---|---|
| **事实分两类，看行首**：他的行抽他的事，她的行抽**她自己的**事 | 「她说：你上次说不吃香菜」是她在复述，不是他在说 —— 只有「这句话说的是她自己吗」为真时才算她的 |
| **她自己的事要抽全**（偏好、习惯、正在做的事、去过的地方，`subject=她`） | 她的偏好在库里没有立足点时，同一件事每一场都靠上下文发挥：今天说爱喝美式、明天说从来不喝咖啡 |
| **她答应他的事**（`kind=promise`，只从她说的话里抽） | 这是「她答应过他的事」进库的**唯一**来源。不放宽这一条，她就会忘了自己答应过什么 |
| **宁少勿错**：没有值得记的就返回 `[]` | 空数组是完全合格的答案。逼模型「必须抽出点什么」的结果是编 |

另外两条与成本直接相关：**不要抽一时的情绪**（「今天好累」说过就过去），
**但要抽长期的**（怕黑、不吃什么、家里人的身体状况）。这两类长得像，
而漏掉后者的代价比多收一条情绪大得多 —— 所以 prompt 里把这条明写出来，
不给模型「听起来像情绪就跳过」的自由。**「她自己的」这条放宽不包括情绪与
眼下的状态**：他说的、她说的「今天好累」都不算事实。记下来只会让她隔天还在问。

## 七道闸

闸的编号在代码里是**锚点**（注释直接写着「闸 4」），别随手改号。

| 闸 | 拦什么 | 落在哪 |
|---|---|---|
| **1 回引轮次** | 没有 `turn_ref` 或 `quote` 的事实：没有证据，直接丢 | `extract.verify` |
| **2 回引校验** | `quote` 必须能在**被回引的那一轮**里定位 | `extract.verify` |
| **3 角色归属** | 他说的话才算事实；她的行只收**她自己的事** —— `kind=promise` 或 `subject=她`；她复述他的话仍然丢 | `extract.verify` |
| **4 时间绝对化** | 相对时间词按那一轮的时间戳换算成绝对日期 | `extract.absolutize` |
| **5 清洗** | 没有内容的（`predicate` + `object` 不足 2 字）、越界的权重 | `extract.clean_fact` |
| **6 冲突消解** | 同槽位（subject + predicate）换值时，旧事实**失效而不是删除** | `extract.resolve_ops` |
| **7 幂等** | 同一段原话整理两次，结果必须一样 | 闸 6 的 NOOP + 内容哈希 id + 游标 |

闸 1–4 住在 `extract.py`，闸 5–7 在它的下游（`clean_fact` / `resolve_ops` 与
`store`）—— 但它们是一条线上的，任何一道省掉都会出问题，所以列在一起。

### 闸 2：三种判决

| 判决 | 条件 | 之后怎样 |
|---|---|---|
| `active` | `quote` 去掉空白标点后能在那一轮里找到 | 落盘，可被检索 |
| `pending` | 覆盖率 ≥ `pending_tolerance`（默认 0.6） | **不丢** —— 进「待确认」，等人点一下 |
| `drop` | 都不满足，或回引到一个不存在的轮次 | 丢弃 |

**校验收窄到被回引的那一轮**，不是全库字符串匹配：全库匹配会放过「上下文里碰巧
出现过这个词」这种巧合命中，而那不构成证据。收窄之后，像「我最近在接私活，
画插画那种」→「职业：插画师」这种合理转述仍然过得去（覆盖率够），
而编出来的引用会被拦下。

`verify(..., tolerance=0.0)` 里的 `0` 表示**用配置里那份**（`pending_tolerance`），
不是「阈值 0」。想表达「什么都收」得传一个正数。

### 闸 4：时间绝对化

模型不知道今天是几号，它写的「上周五」是编的 —— 所以相对时间词一律按**那一轮的
时间戳**换算（`absolutize` 的 `day` 参数基准是那一轮，不是今天）。两层处理：

| 输入 | 处理 |
|---|---|
| 能算准的：`上周五 / 这周三 / 下周一 / 昨天 / 明天 / 后天` | 换成具体日期 |
| 算不准的裸锚点：`上周 / 这个月 / 下个月` | **直接去掉**（把一句会随时间长歪的话留在一条要记很久的事实里，比不写它更糟；准确时间由 `valid_from` 承担） |
| `以前 / 之前 / 最近` | **刻意不动**：它们带的是体貌意义，「我以前住北京」去掉「以前」就把意思改反了 |

**一个错的日期比没有更糟**：她会照着一个不存在的日子问你。所以 `due` 与
`due_day` 只认 `YYYY-MM-DD` 这一种形状（检索与渲染都按 `[:10]` 切，
别的形状会被静默截断）。

### 闸 6：冲突消解与双时间轴

同槽位（`subject` + `predicate`）的三条出路：

```
  槽位是空的        ADD        新事实入
  同槽位已有别的值   SUPERSEDE  新事实入，旧的那条 valid_to 打上、状态变 superseded
  同槽位同值        NOOP       什么都不做
```

**旧事实是失效不是删除**（双时间轴）：长期相处里忘掉一件事比记错一件事更容易被
原谅，但真正伤人的是「她矢口否认说过」。所以「他以前住杭州、现在住上海」两条都
在库里，只有前一条不再是当前事实。

`NOOP` 只出现在返回的统计里、**不写进日志**：日志记的是状态，不是决策流水。
把「这次什么都没发生」也记下来的话，重复整理会让日志无限膨胀。

### 闸 7：幂等

重复整理是常态（崩溃重放、游标自愈、手动催一次），所以两次整理的结果必须一样：

1. 同槽位同值 → `NOOP`，不追加任何操作；
2. 纪要 id 是**内容哈希**（`S-<日期>-<sha1 前 12 位>`），同一段纪要重写会
   `INSERT OR REPLACE` 而不是堆副本（不用内置 `hash()`：它按进程随机化，
   换个进程就换个 id，去重直接失效）；
3. 抽取游标只在**整段成功**之后才推进（失败就下次重试，不会漏也不会重）。
   三种形状不算成功：调用抛错、输出撞上 token 上限（`finish_reason=length`）、
   以及**空正文** —— 契约要的是一份 JSON，空白永远不是合格答案。

   「空正文按失败走」是一条独立的护栏：空响应与「没配模型」（降级跳过，不是失败）
   曾经共用 `""` 这一个返回值，而上游把它读成合格的空答案 —— 形状是
   「抽取 0 条、没有 error、游标照常推进」，同一条链路重跑就绿了。按失败走之后，
   这段原话下次还会被整理，而不是把丢事实推给运气。

## 落到盘上的形状

```json
{
  "op": "ADD", "id": "F-0001",
  "subject": "他", "predicate": "养的猫叫", "object": "团子",
  "quote": "我家猫叫团子", "turn_ref": "T-000001",
  "kind": "fact", "valid_from": "2026-09-01",
  "confidence": 0.9, "importance": 0.6, "persona_attention": 0.5
}
```

两处约定不能改：`quote` **一字不改**（它是证据，改过就不叫证据了，所以时间绝对化
只作用在 `object` 上），事实 id 先占号再写日志（崩溃最多浪费一个号，绝不重号 ——
id 是回引的锚点）。
