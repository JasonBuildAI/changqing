# 检索

> English summary: retrieval runs a constant-cost hot path every turn and an on-demand
> cold path that fuses slot, full-text and vector recall with reciprocal rank fusion,
> reranks by persona weight and recency, then clips to a token budget — and it never
> raises: a timeout or a bad index simply means "nothing to inject this turn".

检索要回答的不是「哪些事实相关」，而是**「这一轮该把什么摆到她面前」**。这两句话
的差别决定了下面每一个数：相关的东西可能有一百条，摆到她面前的只有几百 token。

## 两条路径

| | 热路径 | 冷路径 |
|---|---|---|
| 什么时候跑 | **每轮都跑** | 按需（见下） |
| 成本 | 常数（一条 SQL + 预算裁剪） | 有预算（`recall_ms`，默认 50 ms） |
| 装什么 | 钉住的 + 未兑现的承诺 + 权重最高的一批 | 跟这句话有关的事实 |
| 归属 | 她**一直在意**的事 | 她**这一轮**想起来的这件事 |

热路径是「她始终记得你」的那一半：不问也知道。冷路径是「她这一轮想起来了」那一半。
只有冷路径的话，她平时像个失忆的人；只有热路径的话，她只能聊那几条最重要的。

### 热路径的三档

```
  1. pinned 的事实          无条件进（用户亲手钉的）
  2. 未兑现的承诺 / 约定     整档排在一般事实之前，档内按 due 最早的先
  3. 其余                   按 importance × (0.5 + persona_attention) 排
```

第 2 档**刻意不做条数截断**。只放前 N 条的话，第 N+1 条起既不在钉住那一档、
也不在承诺那一档，于是永远进不了注入集合；而承诺攒得越多，她越看不见 ——
正好与直觉相反。所以承诺整档都在候选里，唯一的截断点是 token 预算。

取数有上界 `hot_fetch_max`（默认 400）：SQL 侧用**与上面完全同序**的
`ORDER BY … LIMIT` 只交回可能进预算的那一段。同序是「先截断」成立的前提 ——
两边顺序不一致时，`LIMIT` 砍掉的就不知道是谁了。

### 冷路径什么时候跑

任一成立即跑（`_cold_triggered`）：

1. 这句话**指向过去**（`上次 / 之前 / 记得 / 你说过 / 那时候 …`）；
2. 热路径这条空，**而库里确实有活跃事实**（第二条不能省：一条事实都没有的新用户，
   每轮都会白跑一次开库）；
3. 与热路径有词面交叠（他正在说的事，库里还有别的相关事实）。

## 三路召回 + RRF 融合

```
  query ──┬── 槽位召回   同槽位的精确事实（subject + predicate）
          ├── 全文召回   FTS5，词面交叠
          └── 向量召回   可选层；没注入 Embedder 时整支不进
                    │
                    ▼
              RRF 融合（只用名次，不用分数）
```

三路各自有 `LIMIT`（`max(8, k × 4)`），先拿 id、再按 id 取行 —— 不把全表取回来
建对象再过滤。库里几千条、预算只装几十条，取数上界是规模上来之后第一件要修的事。

**为什么是 RRF 而不是加权分数**：BM25 和余弦的分数量纲根本不可比，硬凑一个权重
函数只会得到一组只在某次评测里好看的系数。名次没有量纲问题。

融合后的相关度归一：**任一**表里排第一就算相关度 1.0，多表同时命中被
`min(1.0)` 截断（那是「更可信」的加成，不是分数爆表）。不能按「三张表都命中」
当满分 —— 现实中绝大多数查询只命中一张，那样归一出来的相关度永远只有 0.33，
再乘上画像权重与时间衰减，就没有任何一条能过 `min_score`，检索形同虚设。

## 画像重排与时间衰减

```
  score = rel × (0.75 + 0.25 × qual) × recency
  qual    = 0.5 × importance + 0.5 × persona_attention
  recency = 0.6 + 0.4 / (1 + 天数 / 180)          ← 下限 0.6
```

三个系数各有理由：

- `importance` 与 `persona_attention` 各占一半：通用的「重要」和「**她**会在意的」
  不是一回事，后者由注入的画像决定（见 [配置](configuration.md) 的画像一节）。
  它们只影响**排序**，不决定准不准。
- `recency` **带下限**：它是排序信号，不是准入门槛。「他不吃香菜」放一年也还是真的，
  不该被时间直接判死、然后永远注入不进来。

`min_score`（默认 0.35）的真实力气**只在召回窗口的尾巴上**：窗口内的分数下限本来
就高于它，能拦下的是「只命中一张表、又排在尾部、权重与新鲜度都垫底」那一小段。
真正把关的是**召回本身**（槽位要精确相等、全文要有词面交叠、向量要过
`embed_min_cos`）。所以调门槛之前先想清楚它到底在挡什么 —— 把它调高不会让检索
更准，只会让注入更少。

## 预算裁剪：三份预算，各有各的

| 素材 | 预算 | 裁剪方式 |
|---|---|---|
| 事实卡片 | `hot_tokens`（300） | 整条进或整条不进 —— 事实是原子 |
| 故事线（L2 纪要） | `story_tokens`（160） | 散文，`clip_to_tokens` 截断加省略号 |
| 主动话题 | `topic_tokens`（80） | 同上 |

**事实不切一半**：切一半会让模型拿着半个事实说话，那比多花几十 token 贵得多。
散文不适用这条 —— 纪要被截掉尾巴只是不完整，不是错。

第一条豁免预算：**装不下也留着**（预算至少装一条）。否则预算调到比一条事实还小的时候，
她一条都看不到，而配置看起来「正常」。

**注入的总量是三份加起来**（`used_tokens`）。只算事实的话，下一个人会拿它当成
「这一轮的注入量」，而另外两份凭空消失 —— 这正是那种「看起来对、其实漏了」的数字。

## 不重复喂刚说过的话

`exclude_refs` 把最近 `history_window` 轮用过的 L0 轮次排除掉。`history_window`
**必须等于调用方喂给模型的上下文窗口**：小了是「模型刚看过的话又被当记忆喂一遍」，
大了是「掉出窗口的话因为还被排除，所以永远不再注入」。

库不知道宿主的上下文给了多长，所以它是一项配置，而不是这里的一个字面量。

## 绝不抛异常

超时、索引坏、分词器缺失、向量实现没加载 —— 一律只是「这轮没有可注入的」。
理由是这条路上的失败**不该影响她说不说话**：为了省一次检索而让她这一轮开不了口，
是拿产品换整洁。

但吞掉 ≠ 静默。每一次空结果都带一个 `reason`，可以被面板看见：

| reason | 意思 |
|---|---|
| `no_fact` | 库里一条活跃事实都没有（新用户、或者整库被重置过） |
| `no_hit` | 有事实，只是这一问什么都没召回 |
| `timeout` | 算完了，但超了 `recall_ms` —— 这笔时间已经花出去了，这里只是决定它算不算数 |
| `error` | 中间报错了，`last_error()` 里有最近几次的堆栈 |

计时口径：`recall_ms` 覆盖**整条检索**（开连接、三路召回、取行、过滤、融合、打分），
起点在取数**之前**。放在取数之后的话，最贵的那一段压根不在预算里，超时保护形同虚设。
不进预算的是**进程级一次性开销**（分词器建词典、向量实现首次 import）——
那属于启动预热。

## 向量那一层

几件与实现绑在一起的取舍：

- **纯标准库**（`array` + `sum(map(mul, …))`，写入侧预先归一）。不引 numpy：
  核心包零第三方依赖比那几十毫秒值钱。
- **写入侧归一**意味着查询侧只做点积；因此**旧数据必须重建**（`Memory.reindex`）。
- **一次最多扫多少行**：`embed_scan_max`（默认 2000）。这是纯 Python 相似度的
  成本闸门 —— 调大它就要同时想清楚 `recall_ms` 给多少。
- **按 `repo` 认「这批向量是谁编的」**，不只按维度：换一个**同维度**的模型时，
  旧向量会被原样留着，查询向量来自新模型，相似度全是噪声，而统计还报一切正常。
- 相似度门槛 `embed_min_cos`（默认 0.48）在**召回**这一侧把关，不在打分侧。
